# 생기부 리더 — 영역 연동 뷰어 구현 요청

## 만들 것

학교생활기록부 PDF를 읽는 웹 뷰어. 문서 위에 클릭 가능한 영역을 얹고, 오른쪽 패널에 그 영역과 연결된 다른 기록을 띄운다. 쪽을 넘기면 패널도 따라 바뀐다.

해결하려는 문제: 생기부는 수상경력·창의적체험활동·세부능력특기사항이 서로 다른 쪽에 흩어져 있어서, 한 항목을 보면서 관련 기록을 확인하려면 계속 앞뒤로 넘겨야 한다. 이걸 한 화면에서 왕복 가능하게 만드는 게 목적.

사용자: 학생 본인, 학부모, 입시 상담 교사.

---

## 화면 구조

```
┌─────────────────────────────────────────────────────┐
│ 파일명        [영역 표시 ●]   ‹  19 / 24  ›          │
├──────────────────────────────┬──────────────────────┤
│                              │  19쪽                │
│   PDF 펼침 (좌/우 2쪽)        │  수상경력            │
│   ┌──────────┬──────────┐    │  ──────────────────  │
│   │ ▍표 영역 │ ▍표 영역 │    │  이 쪽에서 읽어낸 것 │
│   │          │          │────┼─▶ [연결 카드]        │
│   │ ▍표 영역 │ ▍표 영역 │    │  [연결 카드]         │
│   └──────────┴──────────┘    │  [연결 카드]         │
│                              │                      │
└──────────────────────────────┴──────────────────────┘
        약 65%                        약 35%
```

- 넓은 화면: 좌우 도킹 분할. 패널 `min-width: 330px`, `max-width: 430px`
- **오버레이 모달로 띄우지 말 것.** 펼침 보기에서 패널이 오른쪽 쪽면을 가린다
- 900px 이하: 세로 분할로 전환, 패널이 하단 드로어(높이 약 46dvh)

## 데이터 모델

```ts
type Region = {
  id: string
  page: number
  rect: { x: number, y: number, w: number, h: number }  // 0~1 비율, PDF 페이지 기준
  label: string          // "수상경력 · 1학년"
  links: Link[]
}

type Link = {
  itemId: string
  why: string            // "교과성적우수상 대상 과목" — 필수. 없으면 링크를 만들지 않는다
}

type Item = {
  id: string
  kind: '수상' | '창체' | '세특' | '독서'
  subject: string        // "정보", "자율활동"
  page: number           // 점프 대상
  regionId: string       // 점프 후 깜빡일 영역
  text: string
  chars?: number
}

type Page = {
  no: number
  title: string
  facts: [string, string][]   // [["수상","1학년 7건"], ...] 계산으로 뽑은 값
  links: Link[]               // 영역 미선택 시 쪽 단위로 보여줄 연결
  regions: Region[]
}
```

**좌표는 반드시 0~1 비율로 저장한다.** 화면 px로 저장하면 창 크기·줌·모바일에서 전부 틀어진다.

**영역 겹침 규칙:** 표 전체 영역과 개별 행 영역이 겹칠 수 있다. 면적이 작은 영역이 위에 오고, 작은 영역 바깥의 여백은 큰 영역이 받는다. z-index를 면적 내림차순으로 부여.

## 하이라이트 (3단계)

생기부는 이미 표선 + 빽빽한 명조체다. 채도 있는 면을 얹으면 글자가 안 읽히고, 영역이 10개 넘는 쪽은 파란 얼룩처럼 보인다. 반드시 옅게 간다.

| 상태 | 배경 | 그 외 |
|---|---|---|
| 기본 | `rgba(27,95,217,.065)` | 왼쪽에 2.5px 세로 마커(opacity .55) |
| 호버 | `rgba(27,95,217,.15)` | 마커 opacity 1, 커서 pointer |
| 선택 | `rgba(27,95,217,.2)` | 1.5px 테두리 `#1B5FD9` |

- 툴바에 **영역 표시** 토글. 끄면 기본 배경과 마커가 사라지고, **호버 시에만** 나타난다. 클릭은 계속 가능 — 원문 읽기와 탐색이 공존해야 한다
- 전환 `.12s`

## 상호작용

**영역 클릭**
- 선택 상태로 바꾸고, 패널을 그 영역의 `links`만으로 교체
- 패널 헤더: eyebrow `선택한 영역`, 제목은 `region.label`
- `← 쪽 전체 보기` 버튼 노출. 누르면 쪽 단위 뷰로 복귀
- 같은 영역 재클릭 또는 `Esc` → 선택 해제

**카드 클릭 (왕복이 핵심)**
- `item.page`로 이동 → `item.regionId` 영역을 `scrollIntoView({block:'center'})` → **깜빡임 애니메이션 2회** (약 0.62s × 2, 배경을 .2 → .42 → .2)
- 이 왕복이 되는 순간 체감이 달라진다. 반드시 넣을 것

**쪽 넘김**
- `‹` `›` 버튼 + `←` `→` 키
- 전환 시 크로스페이드 150ms (문서), 130ms (패널)
- **연타 디바운스**: 직전 넘김으로부터 260ms 이내면 페이드를 건너뛰고 즉시 교체. 빠르게 넘길 때 깜빡거리면 멀미가 난다
- 쪽이 바뀌면 영역 선택은 해제

## 패널 내용

두 층으로 나눈다. 섞으면 사용자가 "왜 이게 떴는지" 납득하지 못하고 랜덤 추천처럼 보인다.

**1층 — 이 쪽에서 읽어낸 것** (영역 미선택일 때만)
계산으로 확실히 나오는 값. 수상 건수, 세특 과목 수와 평균 자수, 반복 키워드 빈도 등. 키/값 목록.

**2층 — 연결된 항목**
카드 목록. 각 카드에 반드시 포함:
- 과목/영역 칩 (세특은 파란 칩, 그 외는 회색 칩)
- `19쪽 · 616자` 우측 정렬
- 본문 3줄 클램프
- **근거 한 줄** (`● 교과성적우수상 대상 과목`) — 이게 이 기능의 신뢰도를 만든다. 근거를 못 쓰는 연결은 아예 넣지 않는다
- 영역 선택 시 첫 카드에 `is-target` 강조

**빈 상태** (자주 나온다. 대충 만들지 말 것)
```
연결된 항목이 없어요
이 영역은 다른 기록과 겹치는 내용이 없습니다. 다른 파란 영역을 눌러 보세요.
```
쪽 단위일 땐 마지막 문장을 "다음 쪽으로 넘겨 보세요."로.

## 연결선 (선택 구현)

영역을 선택하면, 문서의 해당 영역 오른쪽 끝에서 패널 첫 카드 왼쪽까지 베지어 곡선을 그린다. `position: fixed` SVG 오버레이, `pointer-events: none`, stroke 1.5px, 양 끝에 r=3 점.

- 문서/패널 스크롤, 리사이즈 시 재계산
- 영역이 뷰포트 밖으로 나가면 숨김
- 900px 이하에서는 비활성

카드의 근거 문구와 짝을 이뤄 "왜 이게 떴는지"를 시각적으로 보강하는 장치다. 과하다고 판단되면 빼도 근거 문구만으로 기능은 성립한다.

## 데이터 파이프라인

**규칙 기반을 우선한다.** 생기부는 NEIS 출력물이라 양식이 고정이다.

1. **파싱** — `3. 수상경력`, `<세부능력 및 특기사항>` 같은 고정 헤더 기준으로 섹션 분할. 표 구조와 좌표는 pdf.js의 텍스트 아이템 transform에서 추출
2. **1층 데이터** — 전부 계산. LLM 불필요
3. **연결 생성 — 규칙 우선**
   - 교과명 사전 매칭: `교과성적우수상(통합사회)` → 통합사회 세특
   - 대회명 내 교과 키워드: `과학수학정보융합부문` → 수학·정보 세특
   - 활동명 일치: `학급 회장` ↔ `학급자치우수상`
   - 결정적이고 설명 가능하다. 이 경로로 만든 근거 문구가 가장 신뢰도가 높다
4. **연결 생성 — 규칙으로 안 되는 것만 LLM**
   - `탐구 주제가 진로활동으로 이어짐` 같은 문맥 판단과 근거 문장 생성
   - **호출 시점: 업로드 직후 1회 배치.** 클릭할 때마다 호출하면 안 된다. 결과를 JSON으로 저장하고 이후 브라우징은 전부 로컬에서 처리
   - 임베딩 유사도를 쓸 경우 근거 문구를 못 만드니, 후보 추리기 용도로만 쓰고 문구는 별도로 생성

**개인정보**: 생기부는 미성년자 개인정보다. 외부 API로 보내기 전 이름·학교명·생년월일을 마스킹하고, 동의 절차와 처리방침을 전제로 설계할 것. 규칙 기반 비중을 높이면 이 부담이 줄어든다.

## 품질 기준

- 영역은 `<button>`으로 만들고 `aria-pressed`, `aria-label`(영역 라벨) 부여
- 키보드: `←` `→` 쪽 넘김, `Esc` 선택 해제, 포커스 링 노출
- `prefers-reduced-motion: reduce`에서 애니메이션·스무스 스크롤 제거
- 세특처럼 카드가 40개 넘는 쪽은 가상 스크롤 검토
- 리사이즈 시 영역 좌표 재계산 (비율 기반이므로 CSS만으로 처리 가능하면 그게 낫다)

## 범위

**1차** — 규칙 기반 연결만으로 전체 흐름 완성. 하이라이트 3단계, 왕복 점프, 쪽 연동, 빈 상태까지.
**2차** — 사용자가 "이건 왜 떴지" 하는 케이스가 쌓이면 그때 LLM 연결을 얹는다. 연결선도 이 단계에서 판단.

## 하지 말 것

- 하이라이트를 진하게 칠하기
- 패널을 문서 위에 오버레이로 띄우기
- 근거 문구 없는 연결 카드
- 클릭할 때마다 API 호출
- 좌표를 px로 저장
- 쪽 넘김마다 패널을 통째로 요란하게 리렌더
