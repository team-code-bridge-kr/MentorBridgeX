# 최근 활동

사이드바의 "최근 작업"(AI 대화 목록)과 대시보드의 "최근 대화"는 이름만 다르고
내용이 같았다. 그런데 사용자가 이 화면에 오는 이유는 "대화를 찾으려고"가 아니라
**"아까 하던 걸 이어서 하려고"** 다. 그래서 대화·기사·그래프·피드백·문서·양식·
음성을 하나의 **최근 활동**으로 묶었다.

핵심은 목록이 아니라 **복원**이다. 항목을 누르면 그때의 대화와 함께 쓰던 기사·
그래프·피드백 문맥이 입력창에 다시 붙는다. 링크만 걸려 있으면 사용자는 기사를
다시 찾아 다시 붙여야 하고, 그러면 이 목록을 쓸 이유가 없다.

## 왜 활동 테이블을 만들지 않았나

이벤트 로그를 새로 쌓는 대신 **기존 테이블을 읽어 묶는다**(`features/activity/service.py`).

- 기록이 두 벌이 되면 언젠가 어긋난다. 그래프에서 노드를 지웠는데 활동 로그에는
  "노드 추가"가 남는 식이다.
- 지금까지 쌓인 데이터에는 활동 로그가 없다. 새 테이블을 만들면 오늘 이전의
  모든 작업이 목록에서 사라진다.
- MBX 에는 `sessionId`·`projectId` 가 없다. 있는 것은 대화와 그 대화가 물고 있던
  문맥 id 뿐이라, 어차피 그것으로 묶어야 한다.

사용자가 목록에 직접 한 일(이름 변경·고정·숨김)만 `activity_meta` 에 저장한다.
그건 다른 어디에도 저장할 곳이 없기 때문이다.

## 무엇을 어디서 읽나

| 유형 | 출처 | 시각 |
|---|---|---|
| 대화 | `assistant_conversations` + `assistant_messages.context` | `updated_at` |
| 기사·논문 | `user_reads` + `articles` | `read_at` |
| 그래프 | Neo4j 노드 `created_at`/`updated_at` | 노드 시각 |
| 피드백 | `comments` | `created_at` |
| 문서 | `document_sections` | `updated_at` |
| 양식 | `form_documents` | `updated_at` |
| 음성 | `voice_sessions` | `updated_at` |

`assistant_messages.context` 에 `{type, id, label}` 이 남아 있어서, **그 대화가
무엇을 놓고 이야기했는지**를 알 수 있다. 이것이 그룹핑과 복원 양쪽의 근거다.

## 묶는 규칙

축은 **대화**다. MBX 의 작업은 대개 "물어보고 → 그 결과를 그래프·문서로 옮기는"
흐름이라, 그 흐름에 이름을 붙일 수 있는 것은 대화뿐이다.

딸린 작업이 대화에 접히려면 **둘 다** 맞아야 한다:

1. 같은 것을 가리킨다 — 대화가 물고 있던 문맥 id 와 같은 기사·코멘트
2. 시간이 가깝다 — 대화가 살아 있던 구간 ±6시간(`FOLD_WINDOW`)

**시간만 가깝다고 묶지 않는다.** 상관없는 두 작업이 우연히 붙으면 목록이 "내가
한 일"이 아니라 "그럴듯한 이야기"가 된다.

**작은 이벤트는 항목이 되지 않는다.** 글 하나를 열었다고, 노드 하나를 추가했다고
줄이 하나씩 생기면 목록이 "읽기 기록"이 되어 정작 이어서 할 일이 그 사이에 파묻힌다.

- 기사·논문 읽기·저장 → 그 글로 대화한 적이 있으면 그 활동에, 없으면 **하루치
  한 덩어리**로 (`read:2026-08-04` · "○○ 외 4건 읽기 / 기사 5건 읽음")
- 그래프 노드 추가 → 같은 날 그래프를 문맥으로 쓴 대화에, 없으면 **하루치 한 덩어리**

결과:

```
[그래프] 내 지식 그래프의 부족한 탐구 영역 찾기
         대화 2개 · 노드 3개 추가                      1분
```

## 제목

대화 제목은 서버가 첫 메시지를 60자로 자른 값이다(`assistant/_title_from`).
그래서 목록에 "하이", "이게 뭐하는거니??" 가 남는다.

제목 우선순위(`features/activity/titles.py`):

1. 사용자가 직접 바꾼 이름 (`activity_meta.title`)
2. **문맥 + 행동 조합** — "이 기사를 …연결할까?" + 기사 제목 → `‘○○’ 지식 그래프에 연결`
3. 쓸 만한 저장 제목
4. 첫 메시지 요약

**2번이 3번보다 앞선다.** 저장 제목이 사실상 첫 메시지와 같은 값이라, "이미 만들어진
제목"으로 대접하면 목록에 늘 첫 문장이 그대로 남는다.

모델을 부르지 않는다. 규칙으로 만들면 같은 대화는 언제나 같은 제목이 나오므로
목록을 그릴 때마다 값이 흔들리지 않고, 따로 저장해 둘 필요도 없다.

## API

| | |
|---|---|
| `GET /v1/activity/recent?limit&kind&q` | 통합 목록. 검색·필터 포함 |
| `PATCH /v1/activity/{key}` | 이름 변경 · 고정 (최대 5개) |
| `DELETE /v1/activity/{key}?delete_source=` | 목록에서 숨기기 |

활동 키는 원본을 가리킨다: `conv:{id}` / `read:{YYYY-MM-DD}` / `graph:{YYYY-MM-DD}` /
`comment:{id}` / `doc:{id}` / `form:{id}` / `voice:{id}`.

**삭제는 기본이 "목록에서 숨기기"다.** 최근 활동에서 지웠다고 그래프·기사·문서가
사라지면 안 된다. 대화만은 사용자가 명시적으로 고를 때(`delete_source`) 함께
지운다 — 그 대화는 이 활동 말고 다른 데서 쓰이지 않기 때문이다. 화면에서는
브라우저 `confirm()` 대신 그 줄에서 바로 묻는다(`.ra-row.is-confirm`).

## 화면

- **사이드바**(`components/sidebar/RecentActivity.jsx`) — 최대 8개. 검색과 필터는
  아이콘으로 접어 두고 누를 때만 편다(폭이 좁아 상시 노출하면 목록 자리를 뺏는다).
  **두 번째 사이드바를 만들지 않는다.**
- **대시보드**(`components/dashboard/RecentActivitySummary.jsx`) — 요약 진입점.
  최신 2개 + "전체 보기". 사이드바와 **같은 엔드포인트**를 쓴다.
- **활동 기록**(`screens/student/S44.jsx`) — 날짜 묶음(오늘/어제/최근 7일/이전),
  검색, 유형 필터. 여기서도 대화와 작업을 탭으로 가르지 않는다.
  제목과 검색이 한 줄, 그 아래 필터, 그 아래 목록. 설명문은 두지 않는다.
  폭 860px 가운데 정렬 + **유리 표면**(`.act-glass`) — 목록만 떠오르고 가장자리는
  비어 보이게 한다. 자세한 규칙은 `docs/design-guide.md` §14.

접힌 레일에서는 목록 대신 아이콘 하나만 남고, 누르면 사이드바가 펼쳐진다.
좁은 화면(≤768px)에서는 사이드바가 가로 막대라 목록이 들어갈 자리가 없으므로,
그 아이콘이 활동 기록 화면으로 보낸다 — 서랍을 하나 더 만들지 않는다.

## 누르면 무슨 일이 일어나는가

`lib/activityRestore.js`. 규칙은 한 문장이다 — **그 활동을 하던 자리로 돌아간다.**

| 활동 | 눌렀을 때 |
|---|---|
| 대화가 있는 활동 | 그 대화를 열고, 쓰던 문맥을 다시 붙인다 (대화 화면) |
| 대화가 없는 활동 (읽기 묶음·그래프 정리·피드백) | 문맥을 붙이고 **물어볼 문장까지 채운다**. 보내지는 않는다 |
| 문서·양식·음성 | 그 화면으로 간다 (대화로 이어갈 것이 없다) |

두 번째 줄이 중요하다. 문맥만 조용히 붙이면 **눌러도 아무 일이 없는 것처럼 보인다**
— 화면은 대시보드 그대로고 작은 칩 하나가 늘 뿐이다. 그래서 무엇을 물을지까지
채워 두고 입력창에 커서를 둔다. 문구는 상단 문맥 카드의 "AI에게 질문"과 같은 것을
쓴다 — 같은 행동에는 같은 문장이어야 한다.

사이드바에서 누르면 화면이 뜨기 전에 신호가 날아가므로, 값을 `lib/handoff.js` 에
잠깐 놔두고 대시보드가 뜰 때 가져간다(이벤트만 쓰면 아직 붙지 않은 리스너에게
소리치는 셈이 된다).
