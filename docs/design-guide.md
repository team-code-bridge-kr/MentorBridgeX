# MBX 디자인 가이드

대시보드(S05)를 다시 만들면서 정한 규칙을 **모든 화면에 적용한 결과**다.
지식 그래프·탐구 피드·발견·생기부 문서·양식·멘토링·음성·알림·통계·설정이
같은 표면·같은 폭·같은 버튼·같은 빈 상태를 쓴다. 새 화면도 여기서 시작한다.

모든 값은 `apps/web/src/theme/styles.css` 상단의 CSS 변수를 쓴다. 색과 반경을
새로 짚어 넣지 말 것 — 한 곳에서 바꿀 수 없게 된다.

**화면 컴포넌트에 인라인 스타일로 색·테두리·그림자를 적지 말 것.** 공용 클래스가
없으면 클래스를 새로 만들어 styles.css 에 둔다. 인라인으로 흩어지면 다음 사람이
"통일"을 다시 해야 한다.

---

## 1. 화면의 성격

**통계를 나열하는 화면이 아니라, 다음 행동을 시작하는 화면이다.**

읽는 순서가 곧 사용 흐름이다.

```
지금 확인할 것(상단 문맥 카드 3장)
  → 쓸 문맥을 고른다(AI에게 질문 / AI 확장 / AI에게 묻기)
  → MBX 에게 묻는다(가운데 입력창)
  → 기사·그래프·피드백이 실제 작업으로 이어진다
```

- 화면 중심은 AI 입력창이다. 나머지 기능(기사·그래프·피드백)은 AI 에게
  **문맥을 넘기는 통로**로 존재한다.
- 기사·그래프·피드백은 **서로 경쟁하지 않는다.** 셋 다 같은 높이·같은 폭·같은
  버튼 크기의 얇은 카드로 위에 서고, 남는 높이는 전부 AI 영역이 가져간다.
  (예전에는 기사 카드만 길었는데, 그건 중요해서가 아니라 항목이 많아서였다.)
- 숫자 카드(총 노드 수, 세션 수 등)는 메인에 두지 않는다. 통계 화면(S28)으로 보낸다.
- 어떤 카드든 주요 액션 중 하나는 반드시 "AI 에게 물어보기" 계열이어야 한다.
  기능이 각자 따로 노는 것처럼 보이지 않게 하는 장치다.
- **문맥을 붙였다고 질문을 보내지는 않는다.** 무엇이 전송될지 눈으로 확인하고
  고칠 기회가 있어야 한다.

### 배치

**배경은 화면을 끝까지 덮는다.** 히어로가 둥근 판으로 떠 있으면 "위젯 하나"가
되는데, 이 화면에서 히어로는 판이 아니라 화면 그 자체다. `.dash-wrap > .hero` 가
바깥 여백과 본문 최대 폭을 음수 마진으로 되밀고 모서리도 둥글리지 않는다. 안쪽
내용(`.hero-inner`)만 980px 로 가운데 정렬된다.

인사말 → 제목 → **문맥 카드 3장** → 입력창(안쪽에 추천 알약 2개) → 추천 탐구 → 최근 대화.
카드가 입력창 **바로 위**에 있는 것이 핵심이다. 페이지 맨 위(인사말 위)에 두면
"먼저 읽어야 하는 것"이 되는데, 이 화면에서 먼저 할 일은 묻는 것이다. 카드는
물을 거리를 고르는 재료다.

### 회전

네 자리가 돈다 — 제목의 단어(2.6초), 관심 기사(8초), 입력창 안 추천 알약
두 개(5초), 추천 탐구(6초). 전부 **제자리에서 내용만** 바뀐다. 틀이 움직이면
아래 내용이 밀린다. 간격을 서로 어긋나게 둔 이유는 둘이 같은 박자로 뛰면
화면이 깜빡이는 것처럼 보이기 때문이다.

추천 탐구에는 화살표와 점을 달지 않는다. 입력창 바로 아래에 조작부가 늘어서면
그게 또 하나의 위젯처럼 보인다. 대신 눌러서 쓰는 문장 하나만 둔다.

자동 회전은 마우스가 올라가거나, 안에 포커스가 있거나, 탭이 뒤로 가면 멈춘다
(`hooks/useCarousel.js`).

**모션을 줄이도록 설정한 사용자에게는 회전을 멈추지 않는다 — 전환 애니메이션만
끈다.** 예전에는 회전 자체를 멈췄는데, 그러면 그 설정을 켠 사람에게는 추천이 하나로
굳어 다른 문장을 영영 못 본다. 줄여 달라고 한 것은 움직임이지 내용이 아니다.

## 2. 레이아웃

| 항목 | 값 |
|---|---|
| **본문 최대 폭** | `--page-w: 1280px` — `.content` / `.rs-wrap` / `.dash-wrap` 의 자식이 자동으로 이 폭 안에 들어간다. 더 좁게 쓸 화면만 `.content-wide`(960) / `.content-narrow`(720) |
| 문장 폭 | 설명·요약·답변 본문은 `74ch` + `word-break:keep-all` |
| 페이지 여백 | `padding:32px 24px 40px` (모바일 `16px 14px 32px`) |
| 히어로 높이 | `--hero-h: calc(100% + 52px)` — dash-wrap 여백까지 되밀어 화면을 끝까지 덮는다 |
| 히어로 최대 폭 | 배경은 **전체 폭**(`.dash-wrap > .hero` 가 여백·`--page-w` 를 되민다), 내용은 `980px` (입력창은 그 안에서 `880px`) |
| 카드 그리드 | `repeat(3,1fr)` / gap 16px → 1100px 이하 2단 → 768px 이하 1단 |
| 카드 높이 | **내용이 정한다.** `min-height` 로 억지로 맞추지 않는다 |

**카드 높이를 맞추지 않는 이유**: 빈 상태 카드(예: "모든 피드백을 확인했어요")가
330px 를 채우느라 쓸데없이 길어진다. 그리드는 `align-items:start` 로 위를 맞춘다.

## 3. 표면(surface)과 테두리

**내용을 담는 표면에는 테두리를 두르지 않는다. 그림자로만 구분한다.**
테두리 상자가 겹치면 화면이 조각조각으로 읽힌다.

- 그림자는 두 단계뿐이다: `--surface-1`(기본) → hover 시 `--surface-2` + `translateY(-1px)`.
- 적용 대상: `.card` `.dash-card` `.area-card` `.sess-card` `.stat-card` `.rs-article`
  `.rs-term` `.notif-item` `.tbl-wrap` — 전부 같은 규칙이다.
- **예외: 선택·입력 컨트롤은 테두리를 유지한다** (`.inp` `.textarea` `.btn-secondary`
  `.rs-track`). 여기서는 테두리가 "조작 대상의 범위"를 뜻한다.
- 반경: 표면 18px, 대화 판 20px, 입력창 18px, 버튼 `--r8`(8px).
  **히어로만 0** — 판이 아니라 화면 전체를 덮는 배경이라 모서리를 두지 않는다.
- 배경은 `--bg1`(흰색)이 기본. **회색 판 위에 흰 카드를 얹지 않는다** — 그림자가
  묻혀 경계가 사라진다. 그래서 `.content` 배경도 흰색이다.

## 4. 색

- 파랑 한 계열만 강조색으로 쓴다: `--blue-500 #0969da`(기본), `--blue-600`(hover),
  `--blue-50`(연한 배경).
- 보조 강조(AI 관련)는 인디고 `--ai-accent #6366f1`. 홀로그램 테두리와 히어로
  글로우에만 쓴다.
- 글자: `--tp`(본문) → `--ts`(보조) → `--tt`(약함) → `--td`(비활성) 순으로 낮춘다.
- 상태색: 성공 `--success`, 주의 `--warning`, 오류 `--danger`.
- 그래프 캔버스도 **나머지 화면과 같은 표면**(`--bg2 #f7f9ff`)을 쓴다. 예전에는
  어두운 판이었는데, 그 대비 하나를 얻는 대가로 이 화면만 다른 앱처럼 보였고 판
  위의 글자·카드·선을 전부 따로 관리해야 했다. 캔버스 위의 값은
  `theme/graphMeta.js` 의 `GRAPH_CANVAS` / `OVERLAY_TEXT` / `OVERLAY_SURFACE`
  한 곳에서만 고친다(대시보드 축소판 `.ctx-graph` 도 같은 값이어야 한다).

## 5. 글자

- 폰트는 Pretendard 하나. 이모지는 TossFace.
- 히어로 제목 `clamp(30px, 3vw, 44px)` / **700(Bold)**. 800(Black)은 문장이 무거워
  보여서 쓰지 않는다. 이 화면에서 제일 큰 글자여야 "무엇을 하는 곳인지"가 먼저
  읽힌다. 고정값으로 크게 잡으면 좁은 화면에서 두 줄로 접히므로 clamp 를 쓴다.
  인사말은 16px.
- 카드 제목 14.5px/700, 본문 13.5px, 보조 설명 12.5px, 메타 11.5px.
- 행간은 본문 1.6~1.8. 제목만 1.34 정도로 좁힌다.
- 인사말 등 히어로 문구도 본문색(`--tp`)을 쓴다 — 회색으로 흐리지 않는다.
- 인사말은 **"안녕하세요! ○○님 👋"**. 쉼표보다 느낌표가 인사에 가깝다.

## 6. 버튼

| 용도 | 클래스 | 모양 |
|---|---|---|
| 주요 행동 (한 화면에 하나) | `btn btn-primary btn-sm` | 파란 배경 + 흰 글씨 |
| 보조 행동 | `btn btn-secondary btn-sm` | 흰 배경 + 얇은 테두리 |
| 텍스트 버튼 | `btn-inline` | 배경 없음, 회색 |
| 추천 실행 | `cs-pill` | 입력창 안 둥근 알약, 두 개씩 회전 |
| 전송 | `composer-send` | **원형** 38px + Enter(⏎) 아이콘 — 첨부 아이콘과 형태로 구분 |
| 피드 저장 | `rs-save` / `rs-save on` | 위 secondary / primary 와 같은 모양 |
| 활동 유형 배지 | `ra-badge` | 연한 회색 알약 — 색으로 유형을 가르지 않는다 |

카드 하단 액션은 **2개까지**만 둔다. 그중 AI 로 보내는 쪽이 primary 다.

숫자·통계에는 색을 칠하지 않는다. `StatCard` 는 기본이 본문색이고, 조치가 필요할
때만 `tone="danger"|"warning"|"success"` 를 준다. 카드마다 다른 색을 칠하면 색이
아무 뜻도 갖지 못한다.

## 7. AI 입력창 (`.composer`)

- textarea 는 최소 52px, 7줄까지 자라고 그다음부터 스크롤.
  Enter 전송 / Shift+Enter 줄바꿈.
- 안쪽 도구는 **첨부(📎)와 음성(🎙) 둘뿐**이다. 링크는 그냥 붙여넣으면 되므로
  버튼을 두지 않는다. **`window.prompt()` 같은 브라우저 기본 창을 쓰지 말 것** —
  디자인이 완전히 다른 창이 뜬다. 입력이 필요하면 화면 안에서 받는다.
- 마이크는 **화면 이동이 아니라 그 자리에서 받아쓰기**다 (`useDictation`).
  질문 한 줄 말하려고 음성 화면까지 갔다 오게 만들면 아무도 쓰지 않는다.
  녹음 중에는 버튼이 빨갛게 뛰고 "듣고 있어요"를 옆에 띄운다. 결과는 기존
  입력을 지우지 않고 **뒤에 붙인다**.
- 테두리는 홀로그램 그라데이션을 `mask-composite:exclude` 로 도려내서 만든다.
  평소 `opacity:.42`, 포커스 시 `1`.

**홀로그램 윤곽선은 포커스했을 때만 켠다.** 기본은 연한 테두리 + 약한 그림자다.
늘 켜 두면 커서가 없는데도 지금 입력 중인 것처럼 보이고, 화면에서 제일 강한 것이
입력창이 되어 버린다. 흐르는 애니메이션도 포커스 중에만 돈다.

**커서는 데스크톱에서만 자동으로 둔다.** 폰에서 들어오자마자 자판이 올라오면
화면 절반이 가려진다. 또 `focus({preventScroll:true})` 로 부른다 — 기본 동작은
입력창을 보이게 하려고 조상 스크롤을 전부 움직여서, 위쪽 카드 가로 스크롤이
밀려 첫 카드가 화면 끝에 붙어 보였다.

### 입력창 안 추천 실행 (`.composer-suggest`)

```
┌───────────────────────────────────────────────┐
│ 질문하거나 기사·논문·영상 링크를 입력하세요      │
│                                               │  ← 한 줄 비운다
│ (오늘의 기사 추천) (‘전염 모형’ 확장하기)        │  ← 5초마다 둘이 함께 바뀐다
│ 📎 🎤                                       ⏎ │
└───────────────────────────────────────────────┘
```

예전에는 입력창 **아래** 알약 5개를 한 줄로 늘어놓았다. 그러면 "고르는 일"이
되고, 정작 눌러야 할 입력창이 뒤로 밀린다.

- **한 번에 둘만.** 다섯이면 고르는 일이 되고, 하나면 마음에 안 들 때 다음 것을
  기다려야 한다. 둘이면 "이런 걸 물어도 되는 곳이구나"가 읽히면서도 고민거리가
  되지 않는다.
- 짝은 한 칸씩 밀며 만든다 — 다섯 개면 (1,2) (3,4) (5,1) (2,3) … 로 돌아 모든
  항목이 골고루 나온다. 뒤엣것이 90ms 늦게 떠서 한 덩어리로 갈리지 않게 한다.
- 비어 있는 입력창은 두 줄 높이(`min-height:52px`)다. 그래서 안내문 아래 한 줄이
  저절로 비고, 알약은 그 밑 도구줄 바로 위에 선다. **띄우려고 여백을 따로 주지
  않는다.**
- 안내문은 textarea 의 진짜 `placeholder` 그대로다. 겹쳐 그리지 않으므로 입력창
  아무 데나 눌러도 커서만 들어간다.
- 글자를 한 자라도 치면 사라진다. 남겨 두면 쓰던 문장을 날리는 버튼이 손 밑에
  놓인다.
- 누르면 **입력창을 채우고 끝난다.** 문장이 입력창 안에서 나왔으므로 그 자리를
  채우는 쪽이 앞뒤가 맞는다(예전 알약은 곧바로 보냈다). 화면 이동 항목(새 사용자
  전용)만 예외로 그 화면으로 간다.

## 8. 문맥 칩 (`.ctx-chip`)

기사·그래프·코멘트를 AI 로 넘기는 표시. **이 앱의 핵심 장치다.**

- 구성: 아이콘 + 종류("기사") + 제목 + 제거(×)
- 아이콘과 종류는 `flex-shrink:0` + `white-space:nowrap`. 폭이 모자라면
  **제목만** 말줄임한다. (안 잡으면 "기/사"로 쪼개진다)
- 종류별 색: 기사=파랑, 코멘트=주황, 그래프/노드=인디고, 파일=회색.

## 9. AI 답변

- 답변에는 **이름표(아바타 + "Bridge AI")** 를 붙인다. 사용자 말풍선과 달리
  답변은 배경이 없어서, 이름표가 없으면 그냥 페이지 본문처럼 읽힌다.
- 본문 폭은 **74ch** 로 제한한다. 넓은 화면에서 한 줄이 120자를 넘으면 눈이
  다음 줄 첫 글자를 못 찾는다.
- 한글은 `word-break: keep-all` — 단어 중간에서 끊기면 읽기가 급격히 나빠진다.
  URL 같은 긴 토큰만 `overflow-wrap: anywhere` 로 넘긴다.
- 목록 번호는 **원문 그대로** 쓴다. CSS 카운터로 다시 세면, 모델이 항목 사이를
  빈 줄로 띄웠을 때 목록이 여러 덩어리로 쪼개져 전부 "1." 이 된다.
- 모델은 마크다운을 섞어 답한다. **반드시 `AnswerText` 로 그린다** — 그대로
  출력하면 화면에 `**별표**`가 보인다. 지원 범위: 굵게, 인라인 코드, 글머리표,
  번호 목록, 제목.
- 마크다운 라이브러리를 새로 들이지 않는다. `dangerouslySetInnerHTML` 도 쓰지
  않는다 — 모델 출력은 신뢰할 수 없는 문자열이다.
- 실행 가능한 제안은 텍스트가 아니라 **카드(툴 호출)** 로 받는다.
  카드에는 반드시 행동 버튼이 달린다.

## 10. 목록 화면의 리듬 (탐구 피드)

같은 카드를 스무 개 늘어놓으면 "오늘 무엇부터 볼지"를 사용자가 스스로 정해야 해서
딱딱하다. 읽는 화면은 **초점 → 후보 → 흐름** 세 단으로 만든다.

1. **히어로 1편** — 큰 시각 판 + 큰 제목 + 요약 3줄 + 행동 버튼
2. **카드 3편** — 판 + 키워드 + 제목 2줄
3. **나머지는 줄글** — 메타 한 줄 / 제목 / 요약 2줄, 구분선으로만 나눈다

맨 위에는 **알약 검색창**을 둔다. 목록 화면의 첫 동작은 대개 "찾기"다.
내 키워드는 그 아래 칩으로 늘어놓아 한 번에 모아볼 수 있게 하고, 등록하지 않은
말로 검색하면 **내 키워드 울타리를 걷는다** — 아직 등록하지 않은 개념을 찾아보려고
검색하는 것인데 등록된 키워드로 한 번 더 거르면 "검색해도 안 나오는" 화면이 된다.
대신 그 자리에서 "내 키워드로 추가"를 제안한다.

앞 4편은 **첫 페이지 것으로 고정**한다. 무한 스크롤로 더 불러올 때마다 맨 위가
바뀌면 읽던 자리를 잃는다. 4편이 안 되면 히어로를 만들지 않고 전부 줄글로 둔다.

**썸네일**은 매체가 붙여 둔 대표 이미지(og:image)를 쓴다. 우리 서버에 내려받아
두지 않고 **주소만 갖고 있다가 원 매체 서버에서 직접 불러온다** — 링크 미리보기와
같은 방식이다. 그래서 출처와 발행일은 **어떤 경우에도 함께 보여야 한다.**

이미지가 없거나 못 불러오면(논문은 거의 없다, 일부 서버는 외부 참조를 막는다)
색 판(`ArticleVisual`)으로 대체한다. **회색 빈 상자를 두지 않는다** — 고장난
화면처럼 보인다. 판에 넣는 글자는 "그 목록에서 무엇이 서로 다른가"로 고른다:
뉴스는 매체명(매체가 섞여 있다), 논문은 키워드(출처가 전부 arXiv 라 매체명으로는
전부 같아 보인다). 색도 같은 글자로 정해서 같은 매체는 늘 같은 색이 되게 한다.

## 11. 대기·빈 상태·오류

- **대기**: 점 세 개만 깜빡이면 멈춘 것처럼 보인다. 이모지 + 한 줄 설명을 함께
  둔다 ("🔎 MBX가 살펴보고 있어요").
- **빈 상태**: 공용 `<Empty title hint cta onCta />` 를 쓴다. 무엇이 없는지 한 줄,
  왜 그런지 한 줄, 다음 행동 버튼 하나. 회색 문장 한 줄만 덩그러니 두면
  "고장난 건가?"로 읽힌다.
- **다 끝낸 상태는 빈 상태와 다르게 쓴다.** "모든 피드백을 확인했어요!" 처럼
  느낌표를 붙이고, 앞에 **파란 체크**(`.ctx-empty-check`)를 둔다. 회색 체크는
  "아무것도 없음"으로 읽히는데 이건 없는 게 아니라 **해낸 것**이다. 초록을 쓰지
  않는 이유는 이 앱의 강조색이 파랑 하나뿐이기 때문이다 — 색이 늘면 뜻을 잃는다.
- **오류**: 실패했다고만 쓰지 말고 "다시 시도" 버튼을 함께 준다.
- **스켈레톤**: 목록은 `ListSkeleton` 으로 자리를 잡아둔다. 로딩 중에 높이가
  바뀌면 화면이 튄다.

## 12. 집중 모드

대화가 시작되면 **상단 문맥 카드·추천 질문·최근 대화를 전부 감춘다.** 답변을
읽는 중에 다른 기능이 옆에 있으면 시선이 흩어진다. 대화 판은 화면 높이를 그대로
채우고 (`min-height: calc(100vh - 72px)`) `chatExpand .34s` 로 확대되듯 들어온다.
입력창이 늘 화면 아래쪽 같은 자리에 있어야 답변을 읽다가 이어서 묻기가 편하다.

대화 머리 왼쪽은 **행동이 아니라 목적지**를 쓴다 — "← 새로 시작하기"가 아니라
"← 대시보드". 새로 시작하기는 사이드바에 이미 있고, 같은 기능을 두 곳에 두면
어느 쪽이 진짜인지 알 수 없다.

감추되 **무엇을 물고 있는지는 남긴다** — 머리 오른쪽에 "사용 중인 문맥 · 기사 1 ·
그래프 1" 한 줄. 보내는 순간 첨부 칩은 비워지므로(그 메시지가 가져갔다), 새로 붙인
것이 없으면 직전 질문이 들고 간 문맥을 보여준다.

### 오늘의 관심 기사

- **뉴스와 논문을 번갈아** 세운다(`useRecommendedArticles`). 최신순으로만 받으면
  한쪽 종류가 카드를 통째로 차지한다 — 실제로 논문만 넉 장 뜬 적이 있다.
  종류별로 따로 받아 끼우되, 한쪽이 모자라면 다른 쪽으로 채운다.
- 종류 꼬리표(`.ctx-kind`)는 뉴스·논문 **모두 회색**. 파랑은 **걸린 내 키워드**
  (`.ctx-kw` 알약)에만 쓴다 — 색이 갈려야 "이건 논문이다"와 "이건 내 관심사다"가
  섞이지 않는다.
- 키워드는 **걸린 것 전부**(최대 3개). 하나만 보이면 우연히 걸린 것처럼 읽힌다.
  다만 없는 키워드를 지어내지 않는다 — 실제로 1~2개인 글이 많다.
- 알약이 "왜 이 글인지"를 말하므로 아래 줄에는 출처와 시각만 둔다. "내 키워드
  ‘X’와 관련된 글입니다"를 또 쓰면 같은 말을 두 번 한다.

### 문맥 카드 규격 (`.ctx-card`)

| 항목 | 값 |
|---|---|
| 높이 | `--ctx-h: 158px` 고정. 내용이 넘치면 자른다 |
| 폭 | `repeat(3, minmax(0,1fr))` — 그냥 `1fr` 이면 제목이 긴 카드만 넓어진다 |
| 테두리 | 연한 실선 + 아주 옅은 그림자 (본문 카드와 달리 테두리를 쓴다) |
| 개수 배지 | 파란 알약이 아니라 옅은 회색 — 카드마다 색이 튀면 위계가 무너진다 |
| 버튼 | `.ctx-btn` 26px. 문맥으로 보내는 것 하나만 `is-primary`(옅은 파랑) |
| ≤1100px | 가로 스크롤 + `scroll-snap`. 셋째 카드만 넓어지지 않게 크기를 유지한다 |

높이를 고정하는 이유는 아래 AI 영역이 흔들리지 않게 하기 위해서다. 그래서 빈
상태·오류·로딩 뼈대도 **같은 높이**를 쓴다.

### 최근 활동 요약 (대시보드)

- 대시보드는 **요약 진입점**이다. 최신 2개만 세우고 "전체 보기"를 제목 줄 오른쪽
  끝에 둔다. 사이드바에 이미 전체 목록이 있으므로 같은 목록을 한 벌 더 두지 않는다
  — 두 곳을 따로 관리하면 정렬이 갈리고 이름이 어긋난다. **같은 엔드포인트**를 쓴다.
- 활동 **이름은 목록에서 바로 고칠 수 있다** — 더보기(⋯) → 제목 변경 → 제자리
  입력(`RenameField`). Enter 저장 / Esc 취소 / 다른 곳 클릭도 저장. 대화 화면
  머리(`.chat-head-title`)에서도 같은 방식으로 고친다.
- 더보기 버튼은 **줄에 커서를 올릴 때만** 보인다. 늘 떠 있으면 목록이 도구 모음처럼
  보인다. `@media (hover:none)` 인 기기에서는 항상 보인다.
- 이름을 바꿔도 **`updated_at` 은 건드리지 않는다.** 이름을 고쳤다고 그 대화가
  방금 한 대화가 되지는 않는다 — 목록 순서가 흔들리면 안 된다.
- 화면을 **먼저** 고치고 서버에 보낸다(`setData`). 한 글자 바꾼 결과를 보여주자고
  목록을 스켈레톤으로 되돌리지 않는다. 실패하면 되돌리고 토스트로 알린다.

## 13. 상단 바 · 내비게이션

- 상단 바(`.hdr`)에는 **화면 제목만** 둔다. 검색·알림·프로필은 사이드바 하단
  (`S_UTIL`)에 있다 — 두 군데에 같은 버튼을 두면 어느 쪽이 진짜인지 알 수 없다.
  (사이드바에 유틸이 없는 관리자 화면에서만 헤더에 남긴다.)
- 대시보드(S05)와 그래프(S06)처럼 화면이 자체 제목을 갖는 경우는 `NO_HDR` 에 넣는다.
- **사이드바 활성 표시는 항상 현재 위치를 가리켜야 한다.** 하위 화면은
  `NAV_ALIAS` 로 상위 메뉴를 이어받는다(노드 상세 → 지식 그래프). 해당하는 메뉴가
  없으면 **아무것도 활성화하지 않는다** — 예전에는 첫 메뉴(대시보드)가 잘못 켜졌다.

## 14. 사이드바

- 맨 위는 **로고(36px, `--r10`) + "팀코드브릿지 MBX"**. 팀 이름은 진하게(700/`--tp`),
  제품 이름은 한 단계 옅게(600/`--ts`) — 팀코드브릿지의 다른 제품(Arena 등)과 같은
  짜임이다. 제품 이름은 문서에서는 MentorBridgeX 지만 **화면에서는 MBX** 로 줄인다.
  브라우저 탭·PWA 이름도 같은 규칙: `MBX | 생기부 관리 솔루션`.
- 로고 그림(`assets/brand/mbx_logo.png`)은 **어두운 배경을 품은 정사각형**이라
  밝은 레일과 어두운 레일에서 같은 파일을 쓴다. 앱 아이콘처럼 모서리만 둥글린다
  (`object-fit:contain`). 밝은/어두운 두 벌을 두던 예전 로고와 달리 분기가 없다.
- 원본은 1024px 이지만 화면에서는 36px 이다. **원본을 그대로 넣지 말 것** —
  1.5MB 를 매번 내려받게 된다. 256px 로 줄여 두었다(49KB).
- 기본은 아이콘 레일(68px). 커서를 올리면 **140ms 뒤에 펼쳐지고 그대로 고정된다.**
  커서가 벗어나자마자 닫히면 메뉴를 고르는 도중에 사라져서 쓸 수가 없다.
- 닫는 방법은 세 가지: « 버튼, Esc, 바깥 클릭. 메뉴를 고르면 자동으로 닫는다
  (고른 화면을 사이드바가 덮고 있으면 안 된다).
- **펼침 상태는 JS 한 곳에서만 정한다.** CSS `:hover` 로도 펼치면, 닫은 뒤에도
  커서가 위에 있는 동안 CSS 가 계속 펼쳐놔서 "닫아도 안 닫히는" 것처럼 보인다.
  키보드용 예외는 `:focus-within` 이 아니라 `:has(:focus-visible)` 이다 —
  마우스로 « 를 누르면 그 버튼에 포커스가 남아 다시 펼쳐진다.
- 여는 조건은 `mouseenter` **와 `mousemove` 둘 다** 본다. 사이드바가 닫히면서
  폭이 줄어도 커서가 그대로면 브라우저는 mouseenter 를 다시 쏘지 않는다.
  그래서 그 자리에서 마우스를 움직여도 안 열리는 "씹힘"이 생긴다.
- 직접 닫은 직후에는 커서가 레일을 벗어날 때까지 자동 열기를 쉰다.
- **고정된 사이드바는 본문 위에 겹치지 않는다.** 자리를 차지해 본문을 밀어낸다.
  잠깐 스치는 hover 라면 덮어도 되지만, 계속 열어두는 상태에서 본문을 가리면
  가려진 것을 보려고 매번 사이드바를 닫아야 한다.
- 상태는 localStorage 에 남겨 새로고침해도 유지한다. **화면을 옮긴다고 강제로
  초기화하지 않는다** — 사용자가 고른 상태가 페이지마다 뒤집히면 설정이 아니다.
- 메뉴 아래는 **최근 활동**(`.ra`). 대화·기사·그래프·피드백·문서·양식·음성이
  하나의 목록이다. 자세한 규칙은 `docs/recent-activity.md`.
  - 최대 8개. 그 아래 "전체 보기"로 활동 기록 화면(S44)에 간다.
  - 검색·필터는 **아이콘으로 접어 둔다.** 폭이 좁아 상시 노출하면 목록 자리를
    뺏는다. 탭을 여러 개 늘어놓지도 않는다 — 기본은 섞인 하나의 목록이다.
  - 유형은 **아이콘과 연한 회색 배지**로만 구분한다. 유형마다 색을 칠하면 목록이
    주요 메뉴보다 강해지고, 색을 못 보는 사람에게는 정보가 되지 않는다.
    배지는 복합 활동이어도 **최대 두 개**.
  - 지금 열려 있는 활동만 연한 파란 배경(`.ra-row.is-active`).
  - **누르면 그 활동을 하던 자리로 돌아간다.** 대화가 있으면 그 대화, 없으면 문맥을
    붙이고 물어볼 문장까지 채운다(보내지는 않는다). 문맥만 조용히 붙이면 눌러도
    아무 일이 없는 것처럼 보인다.
  - 전체 보기는 **활동 기록(S44)** 으로 간다. 이 화면은 상단 바를 쓰지 않는다
    (`NO_HDR`) — 얇은 바에 "활동 기록"만 있고 바로 아래 같은 글자가 또 나오면
    두 줄을 낭비한다. 목록은 다른 화면과 같은 표면 규칙(흰 판 + 그림자)을 쓴다.
    **제목과 검색은 한 줄**, 그 아래 필터 알약, 그 아래 목록. 설명문은 두지 않는다 —
    화면이 무엇인지는 제목과 목록이 이미 말하고, 한 번 읽고 나면 자리만 차지한다.
    폭은 `--page-w`(1280)가 아니라 **860px**. 읽는 목록이라 한 줄이 너무 길면
    제목과 시간이 멀어져 어느 시간이 어느 활동의 것인지 눈으로 이어야 한다.
  - **이 화면만 유리(frosted) 표면**(`.act-glass`)을 쓴다 — §3 의 예외다. 목록
    하나뿐인 화면이라 흰 판을 흰 배경에 얹으면 경계가 안 보이고, 테두리를 두르면
    상자처럼 굳는다. 뒤에 아주 옅은 빛(히어로와 같은 계열)을 깔고 그 위에 반투명
    흰 판을 띄우면 가장자리는 비어 보이고 목록만 떠오른다. **색은 흰색 계열만** —
    강조색은 여전히 파랑 하나다. `backdrop-filter` 를 못 쓰는 브라우저에서는
    `@supports` 로 불투명 흰 판으로 되돌린다(반투명만 남으면 글자가 배경에 묻힌다).
  - 접힌 레일에서는 아이콘 하나만 남는다. **떠 있는 두 번째 패널을 열지 않는다.**

### 지식 그래프 — 학생이 직접 고친다

그래프는 AI 가 생기부에서 뽑아 만든다. 그런데 뽑힌 결과가 늘 맞지는 않는다 —
이름이 어색하거나, 과목이 잘못 붙거나, 정작 중요한 개념이 빠져 있다. **그때
학생이 직접 고칠 수 없으면 그래프는 남의 것이 된다.**

- 만들기·고치기·지우기는 **그래프 화면 안에서** 한다. 다른 화면으로 보내면
  방금 본 그림과 고치는 자리가 떨어져서, 무엇을 고치는 중인지 잊는다.
- 과목·분야는 자유 입력이 아니라 **목록에서 고른다**(`SUBJECT_LEGEND`). 아이콘과
  배치가 그 값으로 정해지므로, 직접 만든 노드도 AI 가 만든 노드와 같은 모양·같은
  자리에 서야 한다.
- 새 노드는 **어디에 이을지**를 함께 묻는다. 잇지 않으면 떨어진 점으로 남는다는
  것도 그 자리에서 말한다.
- **지우기 전에 무엇을 잃는지 말한다** — "연결 N개도 함께 사라집니다".
  되돌리기가 없는 동작이다.
- 만들기 폼은 상세 패널과 **같은 자리**에 선다. 패널을 둘로 늘리면 좁은 화면에서
  캔버스가 사라진다.

**이름표**는 줌 바깥에 그린다(화면 좌표). 노드 안에 같이 두면 확대할 때 글자까지
커져서 아무리 확대해도 빽빽함이 그대로다. 지금은 확대하면 노드 사이만 벌어지므로
가려져 있던 이름이 저절로 드러난다 — "확대하면 글자가 나온다"는 따로 만든 기능이
아니라 이 규칙의 결과다.

- 자리가 겹치면 **덜 중요한 쪽을 지운다**(고른 것 → 검색에 걸린 것 → 이어진 것 →
  핵심 → 과목 → 말단 순). 아래가 막히면 위·오른쪽·왼쪽으로 옮겨 보고, 그래도
  자리가 없으면 그 이름표는 이번 화면에서 뺀다. 다른 노드의 동그라미도 장애물로
  둔다 — 남의 이름표가 동그라미를 덮으면 그 노드가 없는 것처럼 보인다.
- 이름표도 **눌러서 고를 수 있다.** 동그라미보다 넓고, 읽고 나서 누르는 자리다.
- 노드를 고르거나 검색하면 그 노드를 **화면 한가운데로 데려온다**(최소 135%).
  더 키우면 둘레가 사라져서 무엇 옆에 있던 노드인지 알 수 없게 된다. 움직이는
  380ms 동안만 전환을 켠다 — 켜 둔 채로 두면 휠 줌과 드래그가 끈적해진다.

### 음성 도크 — 어느 화면에서든 녹음한다

녹음은 원래 화면 하나(S16)였다. 그런데 **녹음할 상황은 다른 일을 하는 도중에**
생긴다 — 멘토와 이야기하다가, 발표를 들으며, 그래프를 보다가. 화면으로 만들면
녹음하려고 하던 일을 멈춰야 하고, 옮기는 순간 녹음이 끊긴다.

- 도크(`components/voice/VoiceDock.jsx`)는 **앱 껍데기(AppShell)에** 붙는다.
  화면이 바뀌어도 다시 그려지지 않으므로 녹음이 이어진다. 화면 안에 두면 안 된다.
- 접으면 오른쪽 아래 단추 하나. **녹음 중에는 그 단추가 빨갛게 남아 시간을 띄운다** —
  어느 화면에 있든 "지금 녹음 중"이 보여야 한다.
- 녹음 단추는 아래 줄의 **늘 같은 자리**에 있다(입력창의 보내기 단추와 같은 꼴).
  상태에 따라 단추가 옮겨 다니면 멈추려다 다른 것을 누른다.
- 소리 크기 막대를 보여준다. 마이크가 실제로 듣고 있다는 **유일한 신호**다.
- 떠 있는 단추는 **검은 그림자 대신 강조색 번짐**으로 띄운다(`0 0 0 7px rgba(…,.055)`
  + 뒤에 깔리는 옅은 radial). 밝은 배경에 진한 그림자를 깔면 단추만 무겁게 얹힌
  것처럼 보인다. 색은 파랑 한 계열, 녹음 중에는 빨강 한 계열 — 둘을 섞지 않는다.
  접힌 단추와 패널 안 단추가 **같은 재질**이어야 한다. 같은 일을 하는 단추가
  둘인데 생김새가 다르면 다른 기능처럼 보인다.
- 오른쪽 아래는 도크 자리다. 다른 화면의 떠 있는 조작부(그래프 줌)는 그 자리를
  비켜 둔다 — 같은 모서리에 둘이 겹치면 어느 쪽을 누르는지 헷갈린다.
- 녹음은 서버에 남기지 않는다. 옮겨 적은 글만 남기고, 그 사실을 화면에서 말한다.

## 15. 움직임

- 지속시간 120~340ms. `cubic-bezier(.22,.8,.28,1)` 계열을 쓴다.
- **스크롤바는 평소 보이지 않고 커서를 올리면 나타난다.** 본문은 가운데
  정렬(`--page-w`)인데 스크롤바는 창 오른쪽 끝에 붙어 있어서, 늘 떠 있으면
  내용과 상관없는 막대가 가장자리에 하나 더 있는 꼴이다. 그렇다고 아예 없애면
  얼마나 남았는지 알 수 없으므로 hover 로만 남긴다.
- hover 는 120ms 안쪽, 화면 전환은 340ms 안쪽.
- **`prefers-reduced-motion: reduce` 를 반드시 처리한다.** 회전 단어, 홀로그램
  테두리, 손 흔들기, 대화 판 확대 모두 이 설정에서 멈춘다.

## 16. 접근성

- 장식 요소에는 `aria-hidden="true"`. 회전하는 단어처럼 계속 바뀌는 글자는
  `.sr-only` 로 고정 문장을 따로 읽힌다.
- 모든 아이콘 버튼에 `aria-label`. 스트리밍 영역은 `role="log" aria-live="polite"`.
- 포커스 표시는 `outline:2px solid var(--blue-500); outline-offset:2px`. 지우지 말 것.

## 17. 데이터 규칙

- **하드코딩 금지**: 사용자 이름, 기사, 그래프, 코멘트를 컴포넌트에 박아넣지
  않는다. API 가 아직 없으면 mock 서비스/어댑터 레이어로 분리한다.
- 미리보기는 **실제 화면과 같은 데이터·같은 배치·같은 색**으로 그린다.
  요약본을 따로 그리면 미리보기가 아니라 다른 그림이 된다
  (대시보드 그래프 카드가 S06 을 그대로 축소해 그리는 이유).
- 같은 규칙을 두 화면에서 쓰면 공용 모듈로 뺀다 (예: `theme/graphView.js`).

## 온보딩

가입 직후 화면(S03)은 사이드바 없는 `full` 레이아웃이고, 규칙이 조금 다르다 —
카드 하나가 화면 가운데에 서고, 모바일에서는 여백 없이 화면을 채운다. 자세한
규칙과 "왜 이렇게 물어보는가"는 `docs/onboarding.md` 를 본다.

여기서 기억할 것 두 가지.

- **선택 표시는 옅은 파랑**(`--blue-50` + 파란 테두리)이다. 진한 파랑으로 채우면
  "시작하기"와 같은 무게가 되어, 고르는 칸이 화면에서 제일 강해진다.
- **이모지는 TossFace 에 있는 글자만 쓴다.** 없는 글자는 사용자 기기 이모지로
  대체돼서 한 화면에 두 가지 그림체가 섞인다.
