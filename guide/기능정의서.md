# 백엔드 서버 기능정의서

**프로젝트명**: 온톨로지 기반 생활기록부 관리 시스템 (가칭)
**문서 버전**: v0.1 (초안)
**작성일**: 2026-05-05
**작성 범위**: 백엔드 서버 기능

---

## 1. 문서 개요

### 1.1 목적
본 문서는 "온톨로지 기반 생활기록부 그래프 뷰어"와 "STT/RAG 기반 멀티모달 활동 기록 시스템"의 백엔드 서버 기능 요구사항을 정의한다.

### 1.2 시스템 개요
학생의 생활기록부 데이터를 온톨로지(키워드 기반 그래프) 형태로 구조화하여 시각적으로 탐색·편집할 수 있도록 하고, 음성 기반 활동 기록을 그래프에 자동 반영하는 통합 학습 관리 플랫폼.

### 1.3 핵심 가정 (Assumptions)
| 번호 | 가정 내용 | 비고 |
|---|---|---|
| A1 | ML 모델은 공용 베이스 모델 + 사용자별 데이터 분리(RAG/벡터DB) 방식. 향후 개인 파인튜닝 모델로 확장 가능한 구조로 설계 | 비용/확장성 고려 |
| A2 | STT는 녹음 중 라이브 스트리밍 자막을 제공하며, 화자분리/키워드 검증은 녹음 종료 후 후처리 | 정확도 확보 |
| A3 | 그래프와 텍스트는 양방향 동기화하며, 기준 데이터는 그래프 DB | Source of Truth = Graph |
| A4 | ML 추론은 별도 ML 서비스로 분리되어 백엔드는 결과만 수신·저장 | 책임 분리 |
| A5 | 외부 STT API와 자체 STT 모델을 모두 활용 가능하도록 추상화 인터페이스를 둠 | 벤더 종속성 회피 |

## 2. 사용자 정의 및 권한

### 2.1 사용자 유형
| 유형 | 설명 | 주요 권한 |
|---|---|---|
| 학생 | 본인의 생기부 데이터를 입력·관리하는 주 사용자 | 본인 데이터 CRUD |
| 교사 | 담당 학생들의 생기부를 열람·관리하는 사용자 | 담당 학생 데이터 열람/코멘트, 일부 편집 |
| 관리자 | 시스템 운영 담당자 | 전체 사용자/계정 관리, 감사로그 열람 |

### 2.2 인증·계정
- 소셜 로그인 지원 (구글 등 표준 OAuth 2.0 기반)
- 계정 유형 분리: 학생/교사/관리자
- 교사-학생 매핑 관계 관리 (한 교사는 다수 학생, 한 학생은 다수 교사 가능)

## 3. 핵심 기능 1: 온톨로지 기반 생활기록부 그래프 뷰어

### 3.1 기능 목록

| ID | 기능명 | 우선순위 |
|---|---|---|
| F1-01 | 생기부 초기 데이터 입력 (시드 키워드) | 必 |
| F1-02 | 생기부 PDF 업로드 및 파싱 | 必 |
| F1-03 | 온톨로지 그래프 자동 생성 (ML 연동) | 必 |
| F1-04 | 자동 가지치기 추천 (시드 → 하위 키워드 제안) | 必 |
| F1-05 | 그래프 노드/엣지 CRUD | 必 |
| F1-06 | 그래프-텍스트 양방향 실시간 동기화 | 必 |
| F1-07 | 그래프 변경 이력 관리 | 選 |
| F1-08 | 양식 변환 기능 (학과별 생기부 텍스트 생성) | 必 |
| F1-09 | 양식 템플릿 관리 (사전 등록/사용자 정의) | 必 |
| F1-10 | 양식 결과물 저장 및 버전 관리 | 必 |
| F1-11 | 생기부 내보내기 (PDF 등) | 選 |

### 3.2 상세 명세

#### F1-01. 시드 키워드 입력
- 학생이 관심 주제(시드)를 자유 텍스트로 입력
- 시드는 그래프의 루트 노드로 등록
- 다중 시드 지원 (예: "양자컴퓨팅", "환경공학")

#### F1-02. PDF 업로드 및 파싱
- 입력: 생기부 PDF 파일
- 처리: 텍스트 추출 → 영역(세특, 창체, 행동특성, 교과성적 등) 분류 → 구조화 데이터 저장
- 출력: 영역별 텍스트 + 메타데이터(과목, 학년 등)
- ※ 파싱은 별도 ML/파서 서비스에 위임, 백엔드는 결과 수신·저장

#### F1-03. 온톨로지 그래프 자동 생성
- 입력: 영역별 생기부 텍스트
- 처리: ML 서비스에 attention 분석 요청 → 핵심 키워드 및 키워드 간 연결 관계 수신
- 출력: 노드(키워드) + 엣지(관계) 형태로 그래프 DB에 저장
- 제약: 사용자별 데이터 격리 (RAG 벡터스토어 사용자별 분리)

#### F1-04. 자동 가지치기 추천
- 트리거: ① 시드 입력 시점 ② 사용자가 "추천받기" 요청 시점
- 처리: ML 서비스에 현재 그래프 컨텍스트 전달 → 관련 하위 키워드 후보 수신
- 출력: 추천 키워드 리스트 (사용자가 채택/거부)
- 채택 시 그래프에 정식 노드로 추가, 거부 시 기록 후 동일 추천 제외

#### F1-05. 그래프 노드/엣지 CRUD
- 노드 추가/삭제/수정(이름, 속성), 엣지 추가/삭제/관계 변경 모두 지원
- 모든 변경은 즉시 DB에 반영
- 변경 시 연관된 텍스트 영역과의 동기화 트리거 발생 (F1-06과 연계)

#### F1-06. 그래프-텍스트 양방향 동기화
- **그래프 → 텍스트**: 노드 추가 시 ML이 적절한 삽입 위치 제안 → 사용자 확인 → 텍스트 반영
- **텍스트 → 그래프**: 텍스트 직접 수정 시 변경 감지 → 영향 범위만 그래프 증분 업데이트
- 충돌 정책: 그래프 DB를 Source of Truth로, 텍스트는 그래프의 표현 형식으로 간주

#### F1-07. 그래프 변경 이력 관리
- 노드/엣지 변경 시 변경자, 시각, 변경 전/후 값 기록
- 사용자가 이력 조회 및 특정 시점으로 복원 가능

#### F1-08. 양식 변환 (학과별 텍스트 생성)
- 입력: 학과명 또는 키워드 필터, 글자수 제한, 가이드라인
- 처리: 그래프에서 관련 노드 추출 → ML 서비스에 가이드+추출 노드 전달 → 텍스트 생성
- 출력: 정해진 글자수 내 생기부 텍스트

#### F1-09. 양식 템플릿 관리
- 사전 등록 템플릿: 학과별/용도별 가이드라인을 시스템에 내장
- 사용자 정의 템플릿: 학생/교사가 직접 가이드라인·글자수·필수 키워드 등을 정의해 저장
- 템플릿 공유 (교사 → 담당 학생) 가능

#### F1-10. 양식 결과물 저장·버전 관리
- 생성된 텍스트는 결과물 단위로 저장
- 동일 양식에 대해 여러 버전 보관, 버전 간 비교/되돌리기 지원

#### F1-11. 생기부 내보내기
- 양식 변환 결과를 PDF 등 외부 형식으로 다운로드

## 4. 핵심 기능 2: STT/RAG 기반 멀티모달 활동 기록 시스템

### 4.1 기능 목록

| ID | 기능명 | 우선순위 |
|---|---|---|
| F2-01 | 모바일 실시간 음성 스트리밍 수신 | 必 |
| F2-02 | 라이브 STT 처리 (스트리밍 자막) | 必 |
| F2-03 | 후처리: 화자분리, 키워드 검증 | 必 |
| F2-04 | 활동 보고서 자동 생성 | 必 |
| F2-05 | 그래프 자동 반영 (RAG 기반 노드 매칭) | 必 |
| F2-06 | 사용자 검토·승인 워크플로우 | 必 |
| F2-07 | 자동 반영 모드 설정 | 必 |
| F2-08 | STT 엔진 추상화 (외부 API ↔ 자체 모델 전환) | 必 |

### 4.2 상세 명세

#### F2-01. 모바일 실시간 음성 스트리밍 수신
- 입력: 모바일 앱의 마이크에서 캡처된 오디오 스트림
- 통신: WebSocket 또는 동등한 양방향 스트리밍 프로토콜
- 세션 관리: 녹음 시작/중지, 비정상 종료 시 자동 복구

#### F2-02. 라이브 STT 처리
- 음성 청크가 들어오면 STT 엔진에 전달
- 부분 결과(partial)와 확정 결과(final)를 클라이언트에 실시간 전송
- 타임스탬프 포함

#### F2-03. 후처리 (녹음 종료 후 일괄 처리)
- 화자 분리: 발화 구간별 화자 라벨링
- 키워드 검증: 사용자 그래프 내 기존 키워드 대비 매칭/신규 키워드 식별
- 노이즈 제거 및 텍스트 정제

#### F2-04. 활동 보고서 자동 생성
- 후처리 결과를 정해진 양식으로 가공
- **기본 보고서 양식**: 일시 / 장소(선택) / 참여자(화자) / 활동 주제 / 주요 논의 내용 / 핵심 키워드 / 결론·배운 점 / 후속 과제
- 사용자가 양식 커스터마이즈 가능

#### F2-05. 그래프 자동 반영 (RAG 기반 매칭)
- 보고서 텍스트 + 추출 키워드를 ML 서비스에 전달
- ML이 사용자 그래프 DB에서 가장 관련성 높은 노드 위치 식별
- 결과: 매칭된 노드 ID + 삽입/연결 제안

#### F2-06. 사용자 검토·승인
- 기본 동작: 자동 반영 제안을 사용자에게 노출 → 사용자가 승인/수정/거부
- 승인 시에만 그래프에 정식 반영

#### F2-07. 자동 반영 모드 설정
- 사용자 설정으로 "검토 없이 자동 반영" 모드 선택 가능
- 설정 단위: 전체 / 특정 활동 유형별

#### F2-08. STT 엔진 추상화
- 외부 API(예: Whisper API, Clova 등)와 자체 모델을 동일 인터페이스로 호출
- 운영자/사용자 설정으로 엔진 전환 가능
- 엔진별 특성(언어, 화자분리 지원 여부 등) 메타데이터 관리

## 6. 사용자 시나리오 / 유스케이스

### 시나리오 1: 학생의 시드 기반 생기부 구축
1. 학생이 회원가입 후 관심 주제 "양자컴퓨팅"을 시드로 입력한다.
2. 시스템이 관련 하위 키워드(예: "큐비트", "양자 알고리즘", "쇼어 알고리즘")를 추천한다.
3. 학생은 일부를 채택하고, 직접 "암호학"이라는 노드를 추가한다.
4. 시간이 지나면서 노드들이 늘어나고, 자동으로 키워드 간 관계가 시각화된다.

### 시나리오 2: 기존 생기부 PDF 업로드
1. 학생이 학교에서 받은 생기부 PDF를 업로드한다.
2. 시스템이 영역별로 파싱하여 텍스트를 저장하고, 그래프를 자동 생성한다.
3. 학생은 그래프를 보며 빠진 연결이나 부족한 부분을 직관적으로 확인한다.

### 시나리오 3: 동아리 활동 음성 기록
1. 학생이 모바일 앱으로 동아리 회의를 녹음 시작한다.
2. 녹음 중 라이브 자막이 표시된다.
3. 회의 종료 후 시스템이 화자분리·키워드 추출을 거쳐 활동 보고서를 생성한다.
4. 시스템이 보고서 내용과 가장 관련 있는 그래프 노드 위치를 제안한다.
5. 학생이 검토 후 승인하면 그래프에 반영된다.

### 시나리오 4: 학과별 생기부 양식 생성
1. 학생이 "화학과 지원용" 템플릿을 선택한다 (글자수 500자, 가이드 포함).
2. 시스템이 그래프에서 화학 관련 노드를 추출하여 텍스트를 생성한다.
3. 학생은 결과를 검토하고, 마음에 들지 않으면 재생성 요청 또는 직접 수정한다.
4. 최종본은 버전으로 저장된다.

### 시나리오 5: 교사의 학생 관리
1. 교사가 담당 학생 목록에서 한 명을 선택한다.
2. 교사는 학생의 그래프를 열람하고 특정 노드에 코멘트를 단다.
3. 학생에게 알림이 전송된다.

### 시나리오 6: 텍스트 직접 수정 → 그래프 반영
1. 학생이 세특 영역의 텍스트를 직접 편집한다.
2. 시스템이 변경된 영역을 감지하여 영향받는 노드만 재계산한다.
3. 그래프가 증분 업데이트된다.

## 7. 데이터 흐름도 (DFD) 설명

### 7.1 Level 0 (Context)
주요 외부 엔티티는 **사용자(학생/교사/관리자)**, **모바일 앱**, **ML 서비스**, **STT 엔진(외부 API 또는 자체 모델)** 이며, 이들이 **백엔드 시스템**과 상호작용한다.

- 사용자 ↔ 백엔드: 인증, 그래프/생기부 CRUD, 양식 생성 요청
- 모바일 앱 → 백엔드: 음성 스트림
- 백엔드 ↔ ML 서비스: 그래프 추출/추천/매칭/텍스트 생성 요청·응답
- 백엔드 ↔ STT 엔진: 음성 데이터 전달, 텍스트 결과 수신

### 7.2 Level 1 (주요 프로세스)

**P1. 생기부 입력 처리**
- 입력: 시드 키워드 또는 PDF 파일
- 처리: 파싱(PDF의 경우) → 영역 분류 → 영구 저장소(생기부 텍스트 DB)에 저장 → ML 서비스에 그래프 추출 요청
- 출력: 그래프 DB에 노드/엣지 저장

**P2. 그래프 관리**
- 입력: 사용자의 노드/엣지 CRUD 요청
- 처리: 권한 검증 → 그래프 DB 업데이트 → 동기화 모듈 호출(F1-06)
- 출력: 변경 이력 로그, 텍스트 동기화 이벤트

**P3. 그래프-텍스트 동기화**
- 입력: 그래프 변경 이벤트 또는 텍스트 변경 이벤트
- 처리: 변경 방향 판별 → ML 서비스에 위치 제안 또는 증분 추출 요청 → 결과 적용
- 출력: 동기화된 그래프 + 텍스트

**P4. 양식 변환**
- 입력: 템플릿 ID 또는 사용자 정의 가이드 + 필터 조건
- 처리: 그래프에서 관련 노드 추출 → ML 서비스에 텍스트 생성 요청 → 결과 저장(버전 관리)
- 출력: 양식 결과물

**P5. 음성 활동 기록**
- 입력: 실시간 오디오 스트림
- 처리: STT 어댑터 통과 → 라이브 자막 송신 → 종료 시 후처리(화자분리·키워드 검증) → 보고서 생성 → ML 서비스에 그래프 매칭 요청 → 사용자 검토 큐에 적재(또는 자동 반영)
- 출력: 활동 보고서 + 그래프 반영 결과

**P6. 사용자·권한 관리**
- 입력: 로그인, 교사-학생 매핑 변경 등
- 처리: OAuth 인증, 역할 기반 권한 검증
- 출력: 세션 토큰, 매핑 정보

### 7.3 주요 데이터 저장소
| 저장소 | 내용 |
|---|---|
| 사용자 DB | 계정, 역할, 교사-학생 매핑 |
| 생기부 텍스트 DB | 영역별 원본 텍스트, 메타데이터 |
| 그래프 DB | 노드, 엣지, 속성 |
| 벡터 스토어 | 사용자별 임베딩 (RAG용, 사용자 단위 격리) |
| 양식·템플릿 DB | 템플릿 정의, 양식 결과물 버전 |
| 음성·보고서 저장소 | 원본 오디오(임시 또는 영구), 보고서 |
| 변경 이력·감사 로그 | 모든 민감 변경 기록 |

## 8. 외부 시스템 연동 (참고)

| 시스템 | 역할 | 연동 방식 |
|---|---|---|
| ML 서비스 | 그래프 추출, 키워드 추천, 위치 매칭, 텍스트 생성 | 내부 API (REST/gRPC) |
| STT 엔진 (외부 API) | 음성→텍스트 변환 | 추상화된 어댑터 인터페이스 |
| STT 엔진 (자체 모델) | 음성→텍스트 변환 | 동일 어댑터 인터페이스 |
| OAuth Provider | 소셜 로그인 | 표준 OAuth 2.0 |
| PDF 파서 | 생기부 PDF 영역 분류 | 내부 서비스 또는 라이브러리 |

## 9. 비기능적 요구사항 (요약)

| 항목 | 요구사항 |
|---|---|
| 성능 | 사용 시 거부감이 없는 수준의 응답 시간 (구체 수치는 추후 정의) |
| 보안 | 생기부는 민감정보로 분류, 사용자별 데이터 격리, 감사 로그 필수 |
| 확장성 | ML 모델 운영 방식이 RAG → 개인 파인튜닝으로 확장 가능한 구조 |
| 가용성 | 음성 스트리밍 세션의 비정상 종료 복구 지원 |

## 10. 향후 정의 필요 항목 (Open Issues)

1. 구체적 응답 시간/동시 접속 목표치
2. PDF 파서의 정확도 기준 및 영역 분류 스키마 상세
3. 노드 속성 스키마 상세 (현재는 "키워드" 타입만 정의됨, 속성 필드 미정)

5. 음성 원본 오디오 보관 정책 (보관 기간, 삭제 정책)
6. 교사의 학생 데이터 편집 권한 범위 (현재 "일부 편집"으로만 표기)
7. 양식 템플릿의 공유/공개 범위 정책
