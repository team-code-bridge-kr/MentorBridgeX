⭐ 관리자 Tier 체계 (가장 중요)

본 시스템 관리자는 Tier 1(일반)·Tier 2(시니어)로 권한이 명확히 분리됩니다.
Tier 2는 비가역적·시스템 영향이 큰 작업과 데이터 마스킹 해제 권한을 가집니다.

admin.investigation 발동 5단계 절차

모든 [T2] 액션은 다음 순서로 진행:

  1. 1차 확인 다이얼로그 — "정말 진행하시겠습니까?"
  2. 사유 입력 — X-Investigation-Reason 헤더 (10~500자 필수)
  3. 본인 MFA 재인증 (4시간 세션 내 재요청)
  4. 2차 확인 — "이 작업은 되돌릴 수 없습니다"
  5. 실행 + 자동 감사 로그 (severity=critical) + 보안팀 슬랙·이메일 즉시 통보

  • 마지막 사용 역할 기억 (로그인 시 자동 진입)

  • 학생·교사 양쪽 컨텍스트의 알림은 S25에 통합 노출

자동 검증 (CI) 설계 안

v1.0 마감 후 다음 자동 검증을 CI에 통합:

  1. IA 화면 인벤토리 vs 프론트엔드 라우트: 모든 화면 ID에 라우트가 있는지, 모든 라우트가 IA에 있는지
  2. IA 화면 × API 매핑 vs OpenAPI 스펙: 모든 화면의 의존 API가 OpenAPI에 있는지, orphan API 검출
  3. IA 권한 컨텍스트 vs 권한 매트릭스 JSON: 화면별 권한 표기가 매트릭스와 일치하는지
  4. IA 라벨·카피 vs i18n 키 정의: 카피라이팅 단계에서 i18n 키 추출 후 매칭

CI 구현은 백엔드·프론트엔드 팀과 협업하여 v1.0 진입 시점에 셋업.
